# 最佳实践建议

  • 开发环境：允许所有来源（ allowedOrigins("*") ），快速调试。
  • 生产环境：精确配置 allowedOrigins 以增强安全性。
  • 结合全局配置和 Spring Security：确保多层级安全控制。

# 多路径放行

测试了第二个方法，发现 ds 给我的代码只能指定 ip 及端口号处理跨域。以前我 midway 直接配置一下就全都放行了。当然，指定路径肯定更安全。
尝试直接把放行路径改成 * ，出了问题，故问通义灵码，以下是回答：

从错误信息来看，问题出在 CORS（跨域资源共享）配置上。具体来说，当 allowCredentials 设置为 true 时， allowedOrigins 不能包含通配符 * ，因为这会导致 Access-Control-Allow-Origin 响应头无法正确设置。要解决这个问题，有两种方法：

  1. 显式列出允许的源：将具体的域名添加到 allowedOrigins 中。
  2. 使用 allowedOriginPatterns ：这是 Spring 5.3 引入的新特性，允许你使用模式来匹配多个源。

# 解释

  • allowedOrigins ：用于指定允许的源域名。如果需要支持多个域名，可以逐一列出。
  • allowedOriginPatterns ：用于指定允许的源域名模式。这种方式更加灵活，适用于多个子域名或特定模式的域名。
  • allowCredentials(true) ：允许凭证（如 Cookie、HTTP 认证信息等）随请求发送。
    选择其中一种方法进行配置即可解决问题。推荐使用 allowedOriginPatterns ，因为它更灵活且易于维护。

# 放行 localhost

又问了一下怎么可以放行全部 localhost，通义灵码给了回答：

如果你想要允许所有来自 localhost 的源，可以使用通配符 * 来匹配所有端口。但是需要注意的是，使用 * 允许所有源时， allowCredentials(true) 是不允许的，因为这会引发安全问题。
